## Design system — StackGen hero structure

Reference used as read-only inspiration: Figma file `6F630UJfx5RqnXNuWforYJ`, node `1:568`.
Nothing was imported; the pattern was re-implemented in Broker OS tokens.

| Reference pattern | Broker OS application |
|---|---|
| Dark near-black canvas, no gradient stack | Existing `#121214` kept; no glow added |
| Copy column pinned upper-**left**, headline at ~48–52px | 560px column at `x=120, y=92`, headline 50px Inter Bold / 108% |
| White primary CTA + outlined ghost secondary | Waitlist form's white `Join waitlist` button stays primary; new ghost `See the desk` (1px `#38383D`, transparent fill) |
| Product UI floating **bottom-right**, tilted, cropped by the viewport | Teaser tilted 8°, bleeds 301px off the right edge and 141px off the bottom |
| Two stacked UI layers for depth | Depth panel behind at `opacity 0.55`, offset up-right |
| Floating status chip overlapping the UI | `Chip / Draft ready`, human-gated language, same tilt |

### Slant mechanics (Plugin API)

The tilt is applied once, to a wrapper frame, not to each layer:

- Wrapper `Product teaser (slanted)` (`59:2`), 964×621, `clipsContent = false`, holds chip +
  depth panel + window at flat local coordinates.
- Rotation is set via `relativeTransform = [[cos θ, sin θ, tx], [-sin θ, cos θ, ty]]` with θ = **+8°**.
  Using the matrix rather than the `rotation` setter keeps the placement deterministic — the setter
  rotates about the node's centre, so the translation has to be re-solved afterwards.
- **Sign note:** Figma rotation is counter-clockwise-positive, so `+8` tilts the UI *up to the right*,
  which is the direction the reference leans. A negative value would drop the right edge and read as
  a different (heavier) composition.
- `ty` is offset by `sin θ × wrapperWidth` so the *tilted* bounding box lands at a known y — after
  rotation the top-left corner is no longer the topmost point.
- The window and depth panel are `clone()`d from the flat originals (`34:3`, `34:2`) and `rescale(0.86)`d,
  which scales font sizes, radii, stroke weights and shadows together. UI body text lands at ~9.5px —
  small at 1:1, correct for a marketing shot, legible at the 2× export.
- The cloned `Agent overlay` was moved from `x=812` to `x=286` inside the window. In its original
  bottom-right position the right-edge crop swallowed it, and the approve chip is the whole point.

## Platform logos row

Scope is **Meta · Google · LinkedIn · WhatsApp** — the four channels a broker actually works. No

`createImageAsync` is unavailable, so every mark is hand-built geometry:

| Mark | Construction | Colour | Node |
|---|---|---|---|
| Meta | Lemniscate loop, stroked vector, 1.8px round caps | `#0668E1` | `66:6` |
| Google | 312° ring + crossbar, stroked, 1.9px | `#4285F4` | `66:8` |

rainbow logo farm.

**Figma path gotcha:** `vectorPaths` only parses `M / L / C / Q / Z`. SVG arc commands fail with
`Failed to convert path. Invalid command at A`. The Google ring is generated by an in-script
`arcPath()` helper that emits cubic Bézier approximations (control offset `α = 4/3 · tan(Δθ/4)`
per segment, one segment per 90°).

The v9 `+8°` `relativeTransform` tilt was rejected on review: at 1440 the perspective crop swallowed the

`Product teaser (slanted)` (`59:2`) was **deleted**. The replacement is a flat z-stack — no rotation anywhere
in `28:2` or `48:6` (audited: `findAll(n => Math.abs(n.rotation) > 0.01)` returns 0 nodes).

| Element | Node | Geometry (local to wrapper) |
|---|---|---|
| Wrapper `Product teaser (flat)` | `87:2` | `816×492` at `716,122` in hero; `clipsContent = false`, `rotation = 0` |

| `Agent overlay` (inside window) | `87:179` | moved `x 568 → 494` |
| `Chip / Draft ready` | `87:196` | `306×61` at `36,424` |

Craft decisions:

- The window is a `clone()` of the **flat** Product proof window `34:3` (1120×624) `rescale(0.70)`d — not a
  clone of a rotated node. Rescale carries font sizes, radii, stroke weights and shadows together; UI body
  text lands at ~8.7px, legible at the 2× export and correct density for a marketing shot.
- Right-edge bleed is **60px** (window right edge lands at 1500 against a 1440 frame). Inside the 40–80px
  budget: the right rail is trimmed, nothing structural is cropped.
- The agent overlay had to move left. At its inherited `x=568` its right edge sat at abs `1486` — the whole
  point of the shot (`Approve` / `Edit draft`) fell off-frame. At `x=494` the right edge is abs `1412`, fully
  inside the frame with 28px to spare.
- Depth is one plate, not a stack, and it is **the same rectangle offset up-right**, not a scaled or rotated
  copy. Its `Chrome (behind)` child had to be resized to 790 by hand — `resize()` on the parent frame does
  not carry non-auto-layout children, so it initially stuck 70px out to the right.
- The chip breaks the window's **bottom-left** edge instead of floating detached above it. Standalone asset
  `48:6` was already flat; its chip (`75:2`) moved to `132,702` so the export and the hero read as the same
  composition.
